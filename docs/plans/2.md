# Добавление `start_time` и `duration` в `SubprocessResult`

## Контракт и публичный API

Добавить после `killed_by_token`:

```python
start_time: Optional[datetime] = None
duration: Optional[timedelta] = None
```

Для результатов, созданных Suby, действует контракт:

1. `None / None` — `Popen` не создал процесс.
2. `datetime / None` — процесс создан, но завершение не измерено.
3. `datetime / timedelta` — завершение измерено.

`duration` без `start_time` не создаётся. Контракт не применяется к существующим пользовательским `exception.result` и class-level дескрипторам.

## Реализация

### Начало измерения

В `suby/run.py` импортировать:

```python
from datetime import datetime, timedelta, timezone
from time import perf_counter_ns
```

В `_ExecutionState` добавить:

```python
process_start_ns: Optional[int] = None
```

После валидации аргументов, преобразования команды, подготовки окружения и каталога, проверки обработчиков вывода и начального логирования:

1. вызвать `datetime.now(timezone.utc)`;
2. вызвать `perf_counter_ns()`;
3. вызвать `Popen`;
4. после успешного входа в его контекст записать значения в `result.start_time` и `state.process_start_ns`;
5. запустить потоки stdout, stderr и ожидания процесса.

Если `Popen` завершается ошибкой, оба поля остаются `None`. Если ошибка возникает после успешного `Popen`, но до запуска потока ожидания, заполняется только `start_time`.

### Окончание измерения

В `wait_for_process_exit_and_signal()`:

1. вызвать `wait_for_process_exit(process, None)`;
2. при `process.returncode is None` попытаться вызвать `process.wait()`, сохранив нынешнее подавление `OSError`;
3. при `state.process_start_ns is not None` получить конечный `perf_counter_ns()` и записать `duration`;
4. после этого установить `process_exit_event` и `wake_event`.

Значение начальной метки `0` допустимо. При отсутствии метки конечные часы не вызываются, но события устанавливаются.

Подавленный `OSError` не мешает заполнить `duration`, поскольку завершение уже наблюдал `wait_for_process_exit()`. При этом он не гарантирует, что `wait()` успешно завершился и ОС освободила ресурсы дочернего процесса.

### Семантика `duration`

Интервал начинается непосредственно перед `Popen` и заканчивается после наблюдения завершения и попытки финализировать `returncode`.

В интервал входит задержка внутри `Popen`. В него не входят:

- подготовительные операции перед `Popen`;
- ожидание завершения reader-потоков через `join_reader_threads`;
- выход из контекста `Popen`;
- `fill_result`;
- итоговое логирование.

Резервное измерение после выхода из `with Popen(...)` не добавляется.

### Преобразование наносекунд

Добавить:

```python
def _nanoseconds_to_timedelta(delta_ns: int) -> timedelta:
    ...
```

Помощник целочисленно округляет до микросекунд по half-to-even:

```text
0→0, 499→0, 500→0, 501→1,
1499→1, 1500→2, 1501→2 мкс
```

`timedelta(0)` остаётся допустимым измерением.

### Документация

В докстринге `run()` кратко перечислить три состояния контракта и запрет `duration` без `start_time`.

## Правила тестирования

Все проверки новых полей писать непосредственно в тестах; общие тестовые помощники не добавлять.

В докстрингах затрагиваемых тестов кратко указывать соответствующее состояние трёхсостоянийного контракта. Тест пользовательского `exception.result` описывает границу контракта, тесты потока ожидания — внутреннюю реализацию состояния 3 и запрет `duration` без начальной метки.

Для новых полей не добавлять сравнений с реальными часами. Существующие проверки своевременности отмены и защиты от зависания сохранить.
